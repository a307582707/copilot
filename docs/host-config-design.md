# 主机配置模块（详细设计规格）

> 目标：提供一个可维护、可扩展、低缺陷风险的【主机配置】模块（基于 SSH 管理）。
> 本文作为实现与验收依据（前端/后端/运维/产品通用）。

---

## 1. 范围（最小可行版本）与非范围

### 1.1 最小可行版本必做

- 主机、分组、标签管理：增删改查
- 左侧导航：搜索、收藏、分组树、最近连接
- 右侧详情：详情页 + 新增/编辑表单（抽屉/弹窗）
- 本地持久化：localStorage（最小可行版本）或 IndexedDB（增强版）

### 1.2 暂不做（后续）

- 真实 SSH 连接与 Web 终端（需要本地代理 / WebSocket / 安全通道）
- 多用户协作（共享主机、权限、审计）
- 企业级凭据托管（密钥管理服务/钥匙串）

---

## 2. 信息架构

### 2.1 左侧（高频入口）

- 顶部工具区
  - 搜索：按主机名 / 地址（IP 或域名）/ 用户名 / 标签 / 分组 搜索
  - “+”菜单：新增主机 / 新建分组 / 导入 / 导出（最小可行版本可先只做新增主机）

- 列表区（优先级从高到低）
  - 收藏：常用主机置顶（默认显示前 N=10，可“查看全部”）
  - 分组树：推荐两层（项目 → 环境 或 环境 → 项目）
  - 最近连接：最近 N=10
  - 搜索态：只显示搜索结果，并提供“清除搜索”

### 2.2 右侧（承载细节）

- 空状态
  - 未选择主机：提示选择或新增
  - 搜索无结果：提示清除搜索/新增
- 详情页（只读）
  - 基本信息：名称、地址、端口、用户名、分组、标签
  - 连接摘要：认证方式（密码/私钥/代理/无）
  - 操作：编辑、复制地址、（可选）测试连接
- 编辑抽屉/弹窗（可写）
  - 字段校验、保存/取消

## 3. 数据模型（核心：主机信息与凭据分离）

关键原则：不要把明文密码/私钥直接存进主机信息。主机信息通过 `credentialId` 引用凭据。最小可行版本阶段可以先不落地凭据内容，只预留结构。

### 3.1 TypeScript 类型建议（代码保持原样）

```ts
export type ID = string;

export type HostAuthType = 'password' | 'ssh_key' | 'agent' | 'none';

export type Host = {
  id: ID;
  name: string; // 必填 1..60
  address: string; // 必填（IP/域名）
  port: number; // 1..65535（默认 22）
  user: string; // 建议 1..32

  groupId?: ID | null; // 分组
  tagIds: ID[]; // 标签
  favorite: boolean; // 收藏

  credentialId?: ID | null;

  lastConnectedAt?: number | null; // 最近连接（ms）
  createdAt: number;
  updatedAt: number;
  deletedAt?: number | null; // 软删除（可选）
};

export type Group = {
  id: ID;
  name: string;
  parentId?: ID | null;
  sort: number; // 稳定排序
  createdAt: number;
  updatedAt: number;
};

export type Tag = {
  id: ID;
  name: string;
  color?: string;
  sort: number;
  createdAt: number;
  updatedAt: number;
};

export type Credential = {
  id: ID;
  type: HostAuthType;
  // 如果要存，必须加密后再存：base64(ciphertext)
  encryptedPayload?: string;
  createdAt: number;
  updatedAt: number;
};
```

### 3.2 一致性约束（防缺陷必须做）

- `groupId` 指向不存在的分组：加载时自动置为 `null`（未分组）
- `tagIds` 中存在不存在的 `tagId`：加载时自动剔除
- 删除分组：默认不删主机；组内主机 `groupId` 置为 `null`
- 删除标签：从所有主机 `tagIds` 中剔除
- 删除主机：默认不联动删除 `credential`（避免共享凭据被误删）

### 4.2 版本迁移

- 读取必须校验 `version`
- 不匹配：迁移（推荐）或回退默认空数据（并提示）

## 5. 交互规则与边界（缺陷高发点）

- 维护 `activeHostId`
- `activeHost` 被删除/不可见：自动切到下一个可见主机；无主机则进入空状态
- 搜索态：左侧只显示结果；推荐自动选中第一条结果（更稳定）
- 收藏只影响“收藏区”排序，不要影响分组区稳定排序（避免 UI 跳动）
- 连接行为写入 `lastConnectedAt = Date.now()`

---

## 6. 表单校验（明确到规则）

- `name`：必填，去除首尾空白后长度 1..60
- `address`：必填，允许 IPv4/IPv6/域名
- `port`：整数 1..65535（默认 22）
- `user`：可选但建议填写，长度 1..32
- 允许同 `address` 不同 `user/port` 多条（常见）
- `name` 可重复，但列表副标题必须展示 `address:port` 区分

## 7. 体验与交互细化（建议补全，避免后期返工）

### 7.1 选中态与详情联动（强一致）

- 左侧列表必须有**单选**：`activeHostId`
- 右侧详情必须基于 `activeHostId` 渲染；如果找不到（被删/被过滤/被搜索隐藏），按规则自动选中“下一个可见项”
- 建议行为：
  - 初次进入“主机配置”：如果有主机，默认选中第一台（或最近连接第一台）
  - 搜索态：输入后自动选中第一条结果（减少“右侧空白”）

### 7.2 操作入口（最小可行版本建议）

- 左侧顶部 “+”：新增主机（必须）
- 右侧详情页操作：
  - 编辑（必须）
  - 复制地址（必须）：复制 `user@address:port` 或 `address:port`（可配置）
  - 删除（建议）：二次确认 + 支持撤销（可选）

### 7.3 键盘与可用性（建议）

- `Ctrl/Cmd + K`：聚焦搜索框
- `Ctrl/Cmd + N`：新增主机
- `Esc`：
  - 关闭抽屉/弹窗
  - 清空搜索（若搜索框有内容）
- 列表无障碍：按钮可聚焦、回车可选中

## 8. 搜索、排序与分组规则（决定“好不好用”）

### 8.1 搜索策略（建议）

- 搜索字段：`name`、`address`、`user`、分组名、标签名
- 规则：
  - 不区分大小写
  - 支持空格分词（AND）：如 `prod 10.0` 必须都匹配
  - 建议对 `address` 做归一化（去掉端口空格等）

### 8.2 排序策略（建议固定，避免 UI 跳动）

- 收藏区：按 `updatedAt` 或“置顶顺序”排序（可选：手动拖拽排序，后续）
- 分组区：必须稳定排序（`Group.sort` + `Host.sort` 或 `createdAt`）
- 最近连接：按 `lastConnectedAt` 倒序

### 8.3 分组管理（V2 版：更接近 Cursor 的“管理中心”）

> 现状的分组管理仅“增删改”，对真实使用来说偏弱。建议升级为“分组管理中心”，支持结构化分组、排序、统计与批量移动。

#### 8.3.1 分组形态

- **两级分组树**（推荐）：项目 → 环境（或 环境 → 项目）
  - `Group.parentId`：支持子分组
  - `Group.sort`：稳定排序（支持上移/下移、拖拽排序可后续做）
- **空分组可见**：即使分组下没有主机，也必须显示（并展示“暂无主机”）

#### 8.3.2 管理中心 UI（建议）

分组管理弹窗建议拆成三块（从左到右）：

- **分组树面板**（左）
  - 显示两级树
  - 每个分组显示主机数量徽标（含子分组合计/或分别显示）
  - 支持展开/折叠
  - 支持搜索分组名
- **分组详情面板**（中）
  - 分组名称、父级、排序位置
  - 操作：新建同级/新建子分组、重命名、上移/下移
- **主机归属面板**（右）
  - 展示当前分组下的主机列表（可多选）
  - 支持批量移动到其它分组/移出分组（未分组）
  - 支持快速搜索主机（仅在弹窗内过滤）

#### 8.3.3 删除分组策略（必须明确）

删除分组时必须给出策略选择（避免“删分组把主机丢了”）：

- **移出分组**（默认）：分组内主机 `groupId = null`
- **移动到指定分组**：选择目标分组，批量迁移后删除
- **合并分组**：把当前分组并入另一个分组（等价于“移动到指定分组”+删除）
- 删除父分组时：对子分组的处理需要明确
  - 推荐：子分组上提为顶级（`parentId = null`），并保留排序

## 9. 导入 / 导出（后续高频需求，建议现在就定规范）

### 9.1 导出格式（建议 JSON，便于迁移）

- 导出内容：`hosts/groups/tags/credentials`（最小可行版本可先不导出 `credentials.encryptedPayload`）
- 导出必须包含：`version`
- 文件名建议：`host_config_v1_YYYYMMDD.json`

### 9.2 导入策略（必须明确冲突处理）

- 冲突场景：ID 冲突、同名主机、同地址同端口
- 建议提供 3 种策略（最小可行版本可先默认一种）：
  - 追加（ID 重映射）
  - 覆盖（按 ID）
  - 合并（按 address+port+user）
- 导入必须有“预览/校验”：
  - 校验字段合法性
  - 自动清理无效 `groupId/tagIds`
  - 给出导入结果统计（新增/更新/跳过）

## 10. 安全与“编码/乱码”约束（结合当前项目现状必须补）

### 10.1 凭据存储（最小可行版本的底线）

- 最小可行版本：可以只保存 `credentialId/type`，不保存任何敏感内容
- 如果要保存敏感内容（后续）：
  - 必须加密后再存（WebCrypto）
  - 推荐增加“主密码”/“会话解锁”概念
  - 默认不在导出文件里包含密钥材料

### 10.2 中文显示与乱码（已在当前原型出现）

当前项目为了避免 Windows 源码编码问题，在部分位置使用了 `\\uXXXX` 形式的转义。需要明确两条规则：

- **规则 A**：`\\uXXXX` 只能出现在 **JS/TS 字符串字面量** 内（例如 `const s = '\\u4e3b'` 这种写法是错误的；`const s = '\\u4e3b\\u673a'` 在 JS 中也不会解码；正确的是 `const s = '\u4e3b\u673a'` 或直接写中文）
- **规则 B**：不要在 **JSX 文本节点** 中写 `\\uXXXX`（例如 `<div>\\u5f85\\u5b9e\\u73b0</div>` 会原样渲染成 `\\u...`，导致你截图里的现象）

建议工程约束（推荐）：

- 统一把 UI 文案放进 `I18N` 常量（或独立 `i18n.ts`），并通过 `{I18N.xxx}` 渲染
- 源码文件统一 UTF-8；如果确实担心编码，使用**字符串字面量**的 Unicode 转义，不要写到 JSX 纯文本里

## 12. 远程工作区（类似 Cursor：打开目录到新标签页/多工作区 + AI 改文件）

> 目标：连接主机后，将主机目录作为一个“工作区”打开（新标签页或应用内多工作区均可），用户选中文件后发起提问，AI 能自动检索目录并在终端内完成修改；所有变更通过 Git 自动提交并可回滚。

### 12.1 关键概念

- **工作区（Workspace）**：绑定一台主机 + 一个根路径（rootPath），例如 `hostId=xxx, rootPath=/etc/nginx`
- **工作区会话**：包含 SSH 连接信息、当前打开文件列表、当前选中文件列表、当前目录搜索范围等
- **上下文清单**：AI 将读取/搜索的文件列表与大小统计（用户可手动移除，防止“误把整个目录喂给 AI”）

### 12.2 核心体验（用户视角）

- 从“主机配置”里点击 **打开工作区**：
  - 打开新标签页/多工作区视图
  - 标题展示：`主机名 · rootPath`
- 工作区内包含：
  - 左侧：远程文件树 + 搜索框
  - 右侧：文件预览/编辑区 + 终端区
  - 顶部：当前主机连接状态、当前分支/提交状态（Git）
- 用户选中文件后提问：
  - AI 可自动在 `rootPath` 下搜索相关文件（可配置：仅选中文件/允许目录搜索）
  - AI 产出变更以 **diff** 形式展示；用户确认后才执行写入
  - 写入后自动 `git commit`（可配置提交信息模板）

### 12.3 变更闭环（必须可控）

- **强制预览**：AI 输出必须是补丁（diff）或明确的文件修改清单
- **强制确认**：用户确认后才允许执行写入命令
- **自动回滚**（建议二选一，默认 Git）：
  - Git：每次 AI 写入生成一次提交；支持一键回滚到上一个提交
  - 文件备份：写入前生成 `*.bak_YYYYMMDD_HHMMSS`（作为兜底）

#### 12.3.1 回滚动作由 AI 驱动执行（你是编辑器，不要求用户手动敲命令）

- 回滚触发方式（建议二选一，均可做）：
  - **对话驱动**：用户在对话里说“回滚到上一个提交/回滚某个文件/撤销刚才的修改”，AI 生成回滚计划并执行
  - **按钮驱动**：编辑器提供“回滚”按钮，点击后等价于向 AI 发起一个带上下文的回滚指令
- 安全门禁（必须）：
  - AI 在执行回滚前必须展示将要执行的动作（例如：回滚到哪个提交、影响哪些文件）
  - 需要用户二次确认后，Agent 才允许执行（防止误回滚）
  - 回滚后必须再次展示 `git diff` / `git status` 结果作为确认

### 12.4 协议与主机类型（与 Cursor 行为对齐）

- **基础协议**：SSH + SFTP（用于目录/文件读取与传输）
- **Linux/Unix 主机**：默认支持
- **Windows 主机**：
  - 前提：目标 Windows 启用 **OpenSSH Server**（具备 SSH/SFTP）
  - 终端默认 shell 可能是 PowerShell/CMD，命令兼容性需要在 Agent 侧做适配

### 12.5 AI 自动搜索目录（像 Cursor 一样，但要加边界）

- 默认搜索范围：`rootPath` 以内
- 限制与保护（建议）：
  - 最大搜索文件数/总字节数（例如 2000 文件/5MB 索引、单次喂给模型 300KB）
  - 忽略目录：`.git/ node_modules/ dist/ vendor/ .venv/` 等
  - 搜索策略：优先 `rg`/`find`，必要时按扩展名过滤（如 `.conf/.yaml/.py/.ts`）
  - “读写分离”：搜索与读取可自动；写入必须确认

### 12.6 Git 自动提交（你已确认采用此方案）

- 工作区检测：
  - 若目录不是 git 仓库：提示用户初始化/选择仓库根目录（不强制自动 init）
- 提交流程（推荐）：
  - 写入前：`git status` / `git diff`（用于展示预览）
  - 写入后：`git add -A` → `git commit -m "<模板>"`（模板示例：`AI: <任务摘要> (<时间>)`）
  - 可选：为 AI 修改创建独立分支 `ai/<日期>-<短描述>`（降低主分支风险）

#### 12.6.1 回滚策略（AI 执行 + 可审阅）

- 回滚方式优先级（建议）：
  - **优先 revert**（保留历史）：`git revert <commit>`（适合共享仓库/需要保留审计）
  - **可选 reset**（改写历史）：`git reset --hard <commit>`（仅限用户明确选择，且强制二次确认）
- 回滚提交信息模板（建议）：
  - `AI: 回滚 <目标> (<时间>)`
  - 记录触发来源（对话/按钮）与关联的原提交 ID（便于审计）

### 12.7 “AI 在终端修改”落地约束（你已确认）

- AI 不直接操作文件系统 API，而是通过 Agent 执行受控命令
- 建议命令分级（Agent 强制执行策略）：
  - **只读命令**（可自动执行）：`ls`, `cat`, `sed -n`, `rg`, `find`, `git diff`, `git status`
  - **写入命令**（必须用户确认）：`apply_patch`, `git add`, `git commit`, `mv`, `rm`, `sed -i` 等
- 最稳妥的写入方式（推荐）：
  - 让 AI 生成 patch → Agent 用 `git apply` 或自带补丁应用器写入 → 再 `git diff` 校验 → 提交

#### 12.7.1 编辑器形态（网页版/客户端版）对“AI 执行动作”的影响

- 你提供的是编辑器（Web/Client），**回滚/修改/提交等动作由 AI 驱动，但由 Agent 执行**：
  - Web 版：Agent 运行在用户本机（或可控环境）并通过后端接口提供能力
  - 客户端版：可内嵌 Agent（或同机守护进程），接口保持一致，减少两套实现
- 无论 Web/Client：都必须遵守“只读可自动、写入/回滚必须确认”的门禁规则

## 13. 本地 Agent（后续必做：承载 SSH/SFTP/终端/搜索/写回）

> 你已确认后续要做本地 Agent。建议从现在就按 Agent 化的接口设计，避免未来重构前后端边界。

### 13.1 为什么需要 Agent

- 浏览器环境无法安全持有 SSH 私钥与长连接
- 需要稳定执行：目录遍历、文件读取、内容搜索、终端命令、git 操作
- 需要安全策略：命令白名单/确认门禁/审计日志

### 13.2 Agent 职责边界（建议）

- 连接管理：建立/复用 SSH 会话，心跳与断线重连
- 文件能力：list/read/write（SFTP 或命令方式），支持大文件分段读取
- 搜索能力：在 rootPath 内执行 `rg/find` 并返回结构化结果（文件路径 + 命中行号 + 片段）
- 终端能力：执行命令，区分只读/写入，写入必须带“用户确认令牌”
- Git 能力：status/diff/add/commit/checkout（可选分支）
- 审计：记录每次 AI 读了什么、执行了什么命令、改了哪些文件、生成了哪些提交

### 13.3 与现有项目的集成方式（建议）

- 现状后端是 FastAPI（主要做聊天流），建议新增一组 API：
  - `/host/workspaces`：创建/关闭工作区
  - `/host/fs/*`：文件树/读取/搜索
  - `/host/terminal/*`：命令执行（带确认门禁）
  - `/host/git/*`：diff/commit 等
- Agent 可以先以内嵌模式跑在同一后端进程里（MVP），后续再拆成独立进程/服务（你已确认要做独立 Agent）
