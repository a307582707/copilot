# CodeSprite（码灵）官网（Public Site）线框与内容模块规范（2026 v1）

本文覆盖登录前后的官网页面（Public Site），目标是：在保持 Cursor-like 暗色磨砂风格的同时，让“注册→了解→下载→订阅/充值”路径更清晰可转化。

参考与对齐：

- 公共布局与导航骨架：`frontend/src/site/public/layout.tsx`
- Home：`frontend/src/site/public/HomePage.tsx`
- Product：`frontend/src/site/public/ProductPage.tsx`
- Pricing：`frontend/src/site/public/PricingPage.tsx`
- Download：`frontend/src/site/public/DownloadPage.tsx`
- Docs：`frontend/src/site/public/DocsHome.tsx`
- 充值/订阅交互方案：`docs/billing-ui-redesign-2026.md`

## 1. 全局布局（PublicLayout）

### 1.1 Header（导航 + 登录态）

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ Brand(码灵)         Nav: 产品 价格 下载 文档(登录后)      UserMenu/Login    │
└───────────────────────────────────────────────────────────────────────────┘
```

规范：

- Header sticky：滚动后出现边框与磨砂背景（增强层级）
- Mobile：Hamburger → overlay + sheet；Esc/点遮罩关闭
- 登录后：
  - 头像按钮 + Plan badge（Free/Pro）
  - 菜单项：进入控制台(/app)、账号设置(/me)、我的订阅(/pricing 或 /me/billing)、退出登录
- 登录前：
  - 登录（ghost）
  - 注册（primary）

### 1.2 Footer（全站一致）

- 必备：版权、站点域名、手册/安全/联系我们
- 链接应可用（即便是占位，也要确保不会 404 或能给出“占位说明”）

## 2. Auth Gate（登录门禁）

### 2.1 触发场景

- 访问 `/app`（网页版工作区/控制台）必须登录：使用 `ProductGate`（`frontend/src/site/auth/ProductGate.tsx`）。
- 触发后弹 `LoginRequiredModal`（`frontend/src/site/auth/LoginRequiredModal.tsx`），提供：
  - 主按钮：立即登录（携带 next 回跳）
  - 次按钮：返回首页

### 2.2 门禁文案（统一）

- 标题：`需要登录`
- 正文：`请先登录后再进入网页版工作区。`
- confirm：`立即登录`
- cancel：`返回首页`

## 2.3 Auth 页面（/auth/login 与 /auth/register）

> 官网端虽然以 public 为主，但登录/注册页属于“转化关键路径”，需要纳入同一套视觉与状态规范。

### `/auth/login` 登录页

- 目标：登录后跳转到 `next`（默认 `/`；门禁场景一般为 `/app`）
- 状态：
  - loading：按钮显示“登录中…”
  - error：红色错误块（中文友好化）
  - already logged in：自动跳转到 `next`

线框：

```text
Title: 登录
Sub: 登录后可进入网页版使用。
[手机号/邮箱] input
[密码] input (Enter 提交)
ErrorBlock（可选）
[登录]
Link: 还没有账号？去注册（带 next）
```

### `/auth/register` 注册页（短信 + 拼图验证）

- 目标：完成注册并跳转到 `next`
- 关键状态：
  - 获取验证码：需要先完成“安全验证（拼图）”弹窗
  - cooldown：60s 倒计时（按钮显示“重新获取(xx)s”）
  - 错误友好化：短信未授权/模板非法/已注册/验证码错误等必须给出可操作提示

线框：

```text
Title: 注册
[手机号] input
Row: [短信验证码] input + [获取验证码/倒计时] btn
[密码] input
[确认密码] input
ErrorBlock（可选）
[注册并开始试用]
Link: 已有账号？去登录（带 next）

Modal: 安全验证（拼图块拖动对齐缺口）
```

## 3. Home（首页）线框（两种状态）

### 3.1 未登录首页（Hero 版）

目标：一屏说明价值 + 主 CTA（注册）+ 次 CTA（下载）。

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ Badge: v1.2.0 全新发布                                                     │
│ H1: 赋能国内研发团队的 AI 编程助手                                         │
│ H2: （Web + Client 一体化）                                                │
│ 价值主张：统一账号体系/私有化部署/权限审计/发布回滚                         │
│ [免费开始使用]   [下载 Windows 客户端]                                     │
│ 次级：去产品页看完整介绍                                                   │
└───────────────────────────────────────────────────────────────────────────┘
```

关键规范：

- CTA 按钮样式一致（Primary/Ghost），hover 明显
- 链接要避免“跳到需要登录再被打断”：下载、产品页应始终可访问

### 3.2 已登录首页（Portal 版）

目标：减少“我下一步要做什么”的犹豫，直达 /app 与订阅升级。

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ Greeting: 下午好，{name}（{plan}）                                         │
│ sub: 准备开始编码了吗？                                                   │
│ [进入控制台/工作区]   [升级会员]                                           │
├───────────────────────────────────────────────────────────────────────────┤
│ Card: 最新动态                          Card: 你的使用概览(占位)             │
└───────────────────────────────────────────────────────────────────────────┘
```

规范：

- `进入控制台` 是主按钮（减少干扰）
- “使用概览”在无数据前要明确提示：`注：使用统计稍后接入后台数据。`

## 4. Product（产品页）线框与模块规范

目标：更完整讲清楚“为什么是 CodeSprite”，并承接注册/下载转化。

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ HeroLeft: 标题/描述/CTA                                                    │
│ HeroRight: Demo(代码块 + 对话流)                                           │
├───────────────────────────────────────────────────────────────────────────┤
│ 核心特性（三卡）: 补全/对话/私有化                                         │
├───────────────────────────────────────────────────────────────────────────┤
│ 痛点解决方案（交错图文）                                                   │
├───────────────────────────────────────────────────────────────────────────┤
│ 信任背书/技术栈（短段落）                                                  │
├───────────────────────────────────────────────────────────────────────────┤
│ BottomCTA：准备好提升 10x 效率了吗？ [立即注册]                             │
└───────────────────────────────────────────────────────────────────────────┘
```

规范：

- Demo 区：优先“真实截图/动图”，没有素材时用一致占位盒（避免版式塌陷）
- 痛点模块：每条只讲一个“问题→收益”，避免泛泛列举

## 5. Pricing（价格页）线框与转化规范

目标：清晰对比 Free/Pro/Team，减少犹豫点（FAQ），并引导“订阅/充值”。

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ H1: 灵活的计费方案…                                                        │
│ Toggle: 月付 | 年付（省 20%）                                              │
├───────────────────────────────────────────────────────────────────────────┤
│ PlanCards: Free | Pro(高亮推荐) | Team                                     │
├───────────────────────────────────────────────────────────────────────────┤
│ Table: 功能对比                                                            │
├───────────────────────────────────────────────────────────────────────────┤
│ FAQ                                                                        │
└───────────────────────────────────────────────────────────────────────────┘
```

规范：

- Pro 卡片必须“视觉突出 + 风险解释”：高亮边框、推荐 badge、强调核心差异（上下文/稳定/支持）
- CTA 去向：
  - 未登录：引导登录/注册
  - 已登录：引导到订阅/充值（建议最终落到 `/me/billing`，与 `docs/billing-ui-redesign-2026.md` 对齐）

## 6. Download（下载页）线框与可靠性规范

目标：即便后端版本清单未部署，也能给用户“可理解的失败 + 下一步”，同时强化企业分发需要的 SHA256 校验。

### 6.1 下载页主线框

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ H1: 下载 CodeSprite 客户端                                                 │
│ sub: 支持 Windows/(macOS 即将推出)/(Linux 规划中)                           │
├───────────────────────────────────────────────────────────────────────────┤
│ MainGrid:                                                                  │
│  Left: 推荐下载(安装版) + 备用绿色版 + SHA256复制                           │
│  Right: 截图占位(后续替换真实 UI 截图)                                     │
├───────────────────────────────────────────────────────────────────────────┤
│ 安装指引（3步）                                                            │
│ 历史版本/更新日志（最多 6 条）                                              │
│ 系统要求                                                                   │
└───────────────────────────────────────────────────────────────────────────┘
```

### 6.2 数据与状态（/api/public/releases）

下载页依赖 `GET /api/public/releases`：

- loading：`正在加载版本列表…`
- error：`版本列表加载失败：{err}（后端尚未部署时属于正常现象）` + “发布说明”入口（`/docs/publish`）
- empty：`暂无可用 Windows 版本（请先发布构建产物）。`

SHA256：

- 若提供 sha256：展示 `点击复制` 按钮；复制成功短暂显示 `已复制`
- sha256 文本需使用 `code` 样式并允许换行/横向滚动（避免溢出）

## 7. Docs（文档入口）线框

目标：先做“可用的目录”，后续再接入完整文档站；文档入口对运维/发布尤为关键。

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ Title: 使用手册                                                             │
│ Cards: 快速开始 | 计费与充值 | 版本发布(运维) | 安全与隐私                   │
└───────────────────────────────────────────────────────────────────────────┘
```

规范：

- 文档卡片只放“入口 + 一句话说明”，避免把长文堆在首页
- 运维相关页（发布说明）需要提供“可执行步骤 + 校验点”（对齐你仓库现有发布方式）

### 7.1 Docs 子路由（真实存在）

- `/docs`：文档入口卡片
- `/docs/getting-started`
- `/docs/billing`
- `/docs/publish`
- `/docs/security`
- `/docs/contact`

> 建议：公开文档与登录后文档分层（例如“发布说明/安全”可公开；“账号/订阅细节”仅登录后可见），避免入口“登录后才显示但 URL 可直接访问”的一致性问题。

## 8. 公共组件库（Public Site Patterns）

建议抽象成可复用模块（后续落地代码时对应组件）：

- `PublicHeader`：sticky + scrolled state
- `MobileNavSheet`：overlay + sheet + Esc 关闭
- `Hero`：Badge + H1 + H2 + CTA group
- `PlanCard`：标题/价格/权益列表/CTA（支持 highlight）
- `Box`：用于占位与错误提示（Download/Docs）
- `DocCard`：Docs 首页入口卡片

## 9. 与充值/订阅的对齐说明

- 官网的 Pricing/Docs(Billing) 负责“讲清楚规则 + 引导入口”。
- 真正的充值/订阅操作建议收敛到登录后的 `/me/billing`（并按 `docs/billing-ui-redesign-2026.md` 的 Wizard 流程实现），避免在 public 页面做复杂流程导致登录跳转打断。
