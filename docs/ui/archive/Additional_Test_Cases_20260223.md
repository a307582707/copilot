# 补充的 8 个高阶/边界测试用例

这份 70 多个功能的测试清单非常全面，基本覆盖了 CodeSprite 从用户注册到核心工作区（AI 聊天、远程连接）以及后台管理的**所有 Happy Path（主流程）**。

但在实际生产和商业化环境中，往往是**异常路径 (Unhappy Path)、边界条件、并发以及安全机制**最容易导致系统崩溃或客诉。结合目前系统的架构（React 前端 + FastAPI 后端 + HTTP伪终端），我为您补充了 **8 个极具价值的高阶/边界测试用例**，建议将其加入到您的清单中：

### 1. Token 过期与无感刷新兜底（认证与权限）
* **测试点**：登录后，在开发者工具中手动篡改或删除 localStorage/Cookie 中的 Token，或者放置页面数小时让 Token 自然过期，然后点击“资产列表”或发送“聊天”。
* **验证路径**：前端应统一拦截 `401 Unauthorized` 响应，优雅地弹出“登录已过期，请重新登录”的提示，并记住当前路由，重新登录后跳回原页面。绝不能出现点击按钮无反应或控制台疯狂刷红字的情况。

### 2. 伪终端的“黑名单”与防超时机制（工作区功能 - 极度重要）
* **测试点**：在远程终端面板中，故意执行阻塞型或交互式命令（如 `top`, `vim`, `tail -f xxx`, `sleep 100`）。
* **验证路径**：因为目前系统是基于 HTTP POST 的**伪终端**，不支持长连接交互。系统必须**立刻拦截** `top/vim` 等命令并提示“不支持交互式命令”；对于 `sleep 100`，需在达到 HTTP 超时阈值（如 30s 或 60s）后优雅断开并报错，**不能导致后端的 Paramiko SSH 连接池耗尽或界面永远卡死**。

### 3. 超长上下文与大文件附件攻击（聊天功能）
* **测试点**：向 AI 聊天的输入框中直接粘贴长达数万行的日志代码（超大 Payload），或者在有文件上传功能的地方塞入 10MB+ 的文本。
* **验证路径**：前端或网关层必须有文本长度/大小限制。若绕过前端发送到后端，后端应返回明确的 `413 Payload Too Large` 或“Token 数量超限”提示，绝对不能直接 500 崩溃或将整个数据库撑爆。

### 4. 弱网断连与流式响应阻断（系统稳定性）
* **测试点**：在 AI 正在“流式（Streaming）”打字回复的过程中，或者文件树正在加载时，**突然拔掉网线 / 开启 Chrome 的 Offline 模式**。
* **验证路径**：前端能够敏锐捕获流式传输的 `Net::ERR_INTERNET_DISCONNECTED`，立刻停止打字动画，并在输入框或全局抛出红色的“网络已断开”提示；网络恢复后，能正常发起新对话而不需要强制 F5 刷新。

### 5. 极端 UI 遮罩穿透与多指连弹（UI 与交互层）
* **测试点**：在工作区内，快速连续点击左侧 AI 聊天面板、右侧文件抽屉，然后狂按 `ESC` 键，或在有模态框时点击半透明背景。
* **验证路径**：验收此前我们发现的**“P0级全屏遮罩 BUG”**是否死灰复燃。确保不管怎么瞎点，`wsNavFlyoutOverlay` 层都不会一直残留在屏幕上挡住底部输入框，永远能通过点击空白处或 ESC 恢复正常焦点。

### 6. 大批量资产的长列表性能（资产管理）
* **测试点**：通过 API 脚本或后台，给当前测试账号强行挂载 500~1000 台主机资产，然后进入 `/app/assets` 页面。
* **验证路径**：左侧的资产树或列表能否实现**虚拟滚动 (Virtual List)** 或分页？测试页面初始化是否能在 2 秒内完成，点击下拉菜单时浏览器不能有明显的掉帧或卡顿（JS 执行阻塞）。

### 7. 并发扣费防刷与“零余额”边界（计费系统）
* **测试点 1（并发）**：在账户余额极少（如只够发一条消息）的情况下，开多个浏览器 Tab 页，同时按下回车发送耗时极长的 AI 请求。
* **测试点 2（负数）**：余额恰好被扣到 0 的瞬间，系统是否能立即熔断后续对话？
* **验证路径**：后端必须有严格的数据库事务（Transaction）或并发锁，确保余额绝对不会被扣成“负数”；零余额时前端准确弹出“余额不足请充值”的拦截框。

### 8. 错误格式密钥的鉴权容错（资产管理）
* **测试点**：在添加主机的 SSH 凭据时，故意上传一个损坏的私钥文件（不是以 `-----BEGIN` 开头），或者输入错误的 PEM Passphrase（私钥密码）。
* **验证路径**：点击“测试连接”时，不能只泛泛地报“连接失败”，更**严禁把 Python/Paramiko 后端的异常堆栈原封不动吐给前端**；必须翻译成人类可读的“私钥格式错误”或“鉴权失败：密码或密钥有误”。
