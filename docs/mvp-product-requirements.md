## 一、产品定位

### 1.1 产品愿景

> **"每个企业都需要的私有化 AI 知识助手 + 个人运维工作站"**

一款面向**个人运维工程师/DevOps**的轻量级运维工作站，同时具备企业知识管理能力。产品分为两个模式：
- **知识模式**：企业文档管理与 AI 对话（SOP、技术知识、智能问答）
- **运维模式**：资产管理、SSH 终端、日常巡检、监控台账

### 1.2 核心价值

| 价值点 | 描述 |
|--------|------|
| **数据不出网** | 本地部署 Ollama，企业数据完全自主可控 |
| **即插即用** | 最小 2C4G 服务器即可运行，降低使用门槛 |
| **低成本** | 相比云端 AI 服务，运维成本降低 80%+ |
| **开箱即用** | 上传文档即可对话，无需复杂配置 |
| **运维一体化** | 资产+终端+巡检+监控，一站式运维工作站 |

### 1.3 目标用户

| 用户群体 | 核心需求 | 付费意愿 |
|----------|----------|----------|
| **个人运维工程师** | 资产管理、SSH 终端、日常巡检、AI 问答 | ¥9.9/月 |
| **小微企业**（5-50人） | 知识沉淀、SOP 管理、AI 问答 | ¥9.9/月 |
| **中大型企业 IT 部门** | 内部文档管理、技术知识库 | ¥49/月 |
| **运维/DevOps 团队** | 配置文档、故障处理经验积累 | ¥49/月 |

## 三、详细功能需求

### 3.1 文档管理模块

#### 3.1.1 文档上传

**功能描述**：用户上传 Markdown 或 TXT 格式的文档，系统解析并存储。

**需求规格**：

| 字段 | 规格 |
|------|------|
| 支持格式 | `.md`, `.txt` |
| 单文件大小 | 最大 5MB |
| 编码 | UTF-8 |
| 存储路径 | `/data/codesprite/documents/{user_id}/` |
| 元数据 | title（文件名）、content（正文）、created_at、updated_at |

**交互流程**：

```
1. 用户点击「上传文档」按钮
2. 弹出文件选择对话框（支持多选）
3. 系统校验文件格式和大小
4. 解析文档内容（提取标题作为 display name）
5. 保存到数据库 + 本地文件系统
6. 返回成功提示，刷新文档列表
```

**异常处理**：

- 文件格式不支持 → 提示"仅支持 .md 和 .txt 格式"
- 文件超过 5MB → 提示"文件过大，请压缩后上传"
- 解析失败 → 提示"文档解析失败，请检查文件编码"

#### 3.1.2 文档列表

**功能描述**：展示用户上传的所有文档，支持分页和排序。

**需求规格**：

| 字段 | 规格 |
|------|------|
| 分页 | 每页 20 条 |
| 排序 | 按更新时间倒序 |
| 显示字段 | 标题、上传时间、文件大小、操作 |
| 操作 | 查看、删除 |

#### 3.1.3 文档搜索

**功能描述**：通过关键词搜索文档标题和内容。

**需求规格**：

| 字段 | 规格 |
|------|------|
| 搜索方式 | 模糊匹配（LIKE %keyword%） |
| 搜索范围 | 标题 + 正文 |
| 结果展示 | 标题高亮匹配词 |

**API 设计**：

```
GET /api/documents?keyword=运维&page=1&size=20

Response:
{
  "items": [
    {
      "id": "doc_xxx",
      "title": "运维 SOP 手册",
      "content": "...",
      "created_at": 1709234567,
      "updated_at": 1709234567
    }
  ],
  "total": 1,
  "page": 1,
  "size": 20
}
```

### 3.2 AI 对话模块

#### 3.2.1 基础对话

**功能描述**：用户发送消息，Ollama 返回流式回答。

**需求规格**：

| 字段 | 规格 |
|------|------|
| 模型来源 | Ollama（本地） |
| 默认模型 | qwen2.5:1.8b |
| 模型切换 | 用户可在设置中选择已安装的模型 |
| 流式输出 | Server-Sent Events (SSE) |
| 超时限制 | 120 秒 |

**API 设计**：

```
POST /api/chat
Content-Type: application/json

{
  "message": "如何重启 StarRocks 集群？",
  "model": "qwen2.5:1.8b",
  "session_id": "可选"
}

Response (SSE):
data: {"content": "要", "done": false}
data: {"content": "重启", "done": false}
data: {"content": "StarRocks", "done": false}
data: {"content": "集群，", "done": false}
...
data: {"content": "完成", "done": true}
```

#### 3.2.2 对话历史

**功能描述**：保存用户与 AI 的对话记录，支持查看历史。

**需求规格**：

| 字段 | 规格 |
|------|------|
| 存储 | MySQL 表 `chat_sessions` + `chat_messages` |
| 会话列表 | 按时间倒序展示 |
| 上下文 | 最近 10 轮对话作为上下文 |

**数据库设计**：

```sql
-- chat_sessions 表
CREATE TABLE chat_sessions (
  id VARCHAR(36) PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL,
  title VARCHAR(255),
  created_at BIGINT NOT NULL,
  updated_at BIGINT NOT NULL,
  INDEX idx_user_id (user_id)
);

-- chat_messages 表
CREATE TABLE chat_messages (
  id VARCHAR(36) PRIMARY KEY,
  session_id VARCHAR(36) NOT NULL,
  role VARCHAR(20) NOT NULL,  -- 'user' | 'assistant'
  content TEXT NOT NULL,
  created_at BIGINT NOT NULL,
  INDEX idx_session_id (session_id)
);
```

#### 3.2.3 引用文档回答（RAG 简化版）

**功能描述**：当用户提问时，先搜索相关文档，将文档内容作为上下文提供给 AI。

**需求规格**：

| 步骤 | 说明 |
|------|------|
| 1. 意图识别 | 检测问题是否与文档相关（简单关键词匹配） |
| 2. 文档检索 | 搜索匹配的文档片段 |
| 3. 上下文组装 | 将匹配片段拼接到 prompt |
| 4. AI 生成 | 基于上下文生成回答 |
| 5. 来源标注 | 回答中标注引用了哪些文档 |

**Prompt 模板**：

```
你是一个企业知识助手。以下是用户的知识库中与问题相关的文档片段：

---
{文档1内容}
---
{文档2内容}
---

用户问题：{用户问题}

请基于以上文档回答用户问题。如果文档中没有相关信息，请如实说明。
```

### 5.3 Docker Compose 配置

```yaml
version: '3.8'

services:
  app:
    image: codesprite/app:latest
    ports:
      - "8030:8030"
    environment:
      - DATABASE_URL=mysql+pymysql://user:pass@db:3306/codesprite
      - OLLAMA_BASE_URL=http://ollama:11434
    depends_on:
      - db
      - ollama

  db:
    image: mysql:8.0
    environment:
      - MYSQL_ROOT_PASSWORD=rootpass
      - MYSQL_DATABASE=codesprite
    volumes:
      - mysql_data:/var/lib/mysql

  ollama:
    image: ollama/ollama:latest
    volumes:
      - ollama_data:/root/.ollama

volumes:
  mysql_data:
  ollama_data:
```
